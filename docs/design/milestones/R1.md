## 4. 逐项说明

### 4.1 `Result` 的构造函数

文件: `src/zenio/result.h`, `tests/zenio/result_unittest.cpp`。

问题: `Ok(U&& value)` 转调私有构造函数 `Result(std::forward<U>(value))`。`T` 和 `E` 是同一种类型时 (比如 `Result<std::error_code>`, `E` 的默认值就是它), 这个调用和 `Result(E err)` 的参数类型相同, 重载决议优先选非模板的那个, 结果成了 `Err`。设计会话实测: `Result<std::error_code>::Ok(ec)` 得到 `Err`, `Result<int, int>::Ok(7)` 同样, 左值和右值实参都复现。

改法见 design/error.md 2.2, 公开接口不变:

- `Result` 的 private 区加两个标签类型 `OkTag`、`ErrTag`。
- 两个私有构造函数改成带标签参数的 `Result(OkTag, U&& value)` 和 `Result(ErrTag, E err)`, 类外定义同步。
- `Ok(U&& value)` 改成 `return Result(OkTag {}, std::forward<U>(value));`。
- `Err(E err)` 改成 `return Result(ErrTag {}, std::move(err));`。

这个修法设计会话在临时副本上验证过: 问题消失, 原有的 10 个 `Result` 单测照常通过。

测试: 按 design/error.md 第 7 节新增一条用例, `T` 和 `E` 相同时 `Ok` 是 Ok 且 `value()` 等于传入的值, `Err` 是 Err; 左值和右值实参都要覆盖; `Result<std::error_code>` 和 `Result<int, int>` 都要测。

### 4.7 `Try` 的报错

文件: `src/zenio/try.h`。

`T` 是引用类型时, `Result<T, ...>` 里的 `std::variant` 不能放引用, 现在的报错出现在 `<variant>` 内部, 不直观。给 `Try` 加一个约束, 写法见 design/error.md 2.3:

```cpp
template <class T>
    requires(!std::is_reference_v<T>)
[[nodiscard]] ZENIO_EXPORT Task<Result<T, std::exception_ptr>> Try(Task<T> task) {
```

不要用函数体里的 `static_assert`, 设计会话试过, 不起作用: 返回类型先被实例化, 那里已经出错, 编译器不会再去实例化函数体。

设计会话验证过约束的写法: `Try(Task<int>)` 和 `Try(Task<void>)` 照常编译, `Try(Task<int&>)` 的报错指向 `!std::is_reference_v<int &>`。

### 4.8 `SocketAddr::Parse` 收紧

文件: `src/zenio/net/address.cpp`, `tests/zenio/net/address_unittest.cpp`。

规则见 design/net.md 4.1, 相比现在有两处变化:

- IPv6 形式要求 `[` 是第一个字符。现在 `"x[::1]:80"` 会被接受。
- IPv4 地址自己解析, 不再交给 `inet_pton`: 四段, 每段 1 到 3 个十进制数字, 不超过 255, 除 `0` 之外不允许前导零。现在 `"010.0.0.1:80"` 在 macOS 上被接受, 而两个平台对这种写法的处理不一致。

测试: 按 design/net.md 第 7 节「解析的严格性」补用例。

## 7. 实现偏差

1. **4.6 的项目头写成了引号形式 `#include "zenio/zenio.h"`, 不是尖括号**。
   - 原因: `.clang-format` 的 IncludeCategories 只把引号形式的 `zenio/` 头识别为第一组 (项目头), 尖括号形式一律归进标准库组并按字母重排, `<zenio/zenio.h>` 会被排到 `<cstdio>`、`<utility>` 之后, 与本任务书 4.6 要求的顺序和验收第 7 条 (clang-format 无差异) 冲突。
   - 实际做法: 用 `#include "zenio/zenio.h"`, 与仓库其余文件的项目头写法一致, 顺序保持稳定。`std::size_t` 所需的 `<cstddef>` 由 `zenio.h` → `join_set.h` 传递提供, 不另加进第二组 (第二组保持 4.6 列出的 `<cstdio>`、`<utility>`)。
   - 同步修改: 无。
