## 5. 实现要求

### 5.1 签名

- 函数、类、命名空间、头文件归属都和子系统文档一致。文档里写"同上"的地方, 按上下文补成具体类型。
- awaiter 类在 M1 只有 `await_ready`、`await_suspend`、`await_resume` 三个成员函数和一个私有构造函数。私有构造函数需要友元时, 让创建它的那个函数或类成为友元。

文档里的公开声明验证过: 在 Apple Clang 21 上拼成一个翻译单元做只编译检查, 包含 1.8 的目标用法和一段覆盖全部公开 API 的用法, `-Wall -Wextra` 下没有错误和警告。所以按文档写不会遇到签名层面的问题; 真遇到了, 先对照文档检查是不是抄错了, 再记偏差。

### 5.2 协程 promise 的编译期要求

`Task<T>` 的 `promise_type` 要让目标用法里的协程能编译:

- `final_suspend()` 和 `unhandled_exception()` 标了 `noexcept`。
- `initial_suspend()`、`final_suspend()` 的返回类型 `InitialAwaiter`、`FinalAwaiter` 是完整类型, 有 `await_ready`、`await_suspend`、`await_resume` 的声明。
- `Task<T>::Awaiter::await_suspend` 返回 `std::coroutine_handle<>`。

### 5.3 例外: 可以写在头文件里的实现

只有编译期就需要、或者模板没法分离的这几处:

- `promise_type::await_transform` 的透传, 一行。
- `YieldAwaiter`、`InitialAwaiter`、`FinalAwaiter` 的 `await_ready` 和空的 `await_suspend`, 文档里是空的。
- `Try` 的整个函数, design/error.md 2.3 给了完整实现。
- `Result` 的类型别名, 以及 `= default`、`= delete` 的特殊成员函数。

其余全部只有声明。

## 8. 实现偏差

1. **`detail::SelectOutputType` concept 定义在 `zenio/detail/awaiters.h`, 不在 `select.h`**。
   - 原因: `SelectAwaiter` 的私有构造函数靠友元声明授权给 `zenio::Select`。实测 (Apple Clang 21) 友元声明必须带上与 `Select` 完全一致的 `requires` 约束才能授予访问权; 声明无约束、定义带约束时, 调用能解析但友元不生效。这个约束引用 `SelectOutputType`, 而友元声明在 `awaiters.h` 里必须先于 `select.h` 出现, 所以 concept 必须在 `awaiters.h` 可见。
   - 实际做法: concept 定义移入 `zenio::detail` (`awaiters.h`), `select.h` 只使用它。
   - 同步修改: design/select.md 2.1。

2. **`awaiters.h` 的前置声明清单比 design/task.md 2.3 列出的多**。
   - 原因: 限定名的友元声明必须有先前声明, 未声明过的直接编译错误 (实测)。需要友元的创建方一共六个: `zenio::JoinHandle` (类)、`zenio::SpawnAndSeize`、`zenio::Uncancellable`、`zenio::Select`、`zenio::Sleep`、`zenio::SleepUntil` (函数/模板), 它们的声明都要在 `awaiters.h` 里先出现一次, 与各自头文件里的声明逐字一致。
   - 实际做法: 在 `awaiters.h` 中按上述清单前置声明, 并注明"与各自头文件保持一致"。
   - 同步修改: design/task.md 2.3。

3. **`SelectResult<Ts...>` 无法按 design/task.md 2.3 的说法在 `awaiters.h` 里前置声明**。
   - 原因: 别名模板没有前置声明这种形式, 只能连同定义一起出现; 而 `SelectAwaiter::await_resume()` 按 design/select.md 第 3 节直接写 `std::variant<VoidToMonostate<await_result_t<A>>...>`, 并不引用这个别名。
   - 实际做法: 不在 `awaiters.h` 里声明 `SelectResult`, 它只在 `select.h` 里定义。
   - 同步修改: design/task.md 2.3。

4. **`result.h` 包含 `zenio/detail/export.h`** (M1 §5.4 原文是"result.h 不依赖其它项目头")。
   - 原因: `Result` 按约定标注 `ZENIO_EXPORT`, 宏必须有定义才能编译。M1 的编译检查碰巧都先包含了定义宏的头 (如 `zenio.h` 经由 `cancel.h`), 问题在 M2 让 `result.h` 独立参与构建时暴露。
   - 实际做法: `result.h` 直接包含 `zenio/detail/export.h`, 依赖方向无环。
   - 同步修改: 本文件 5.4 的依赖方向图; build.md 2.4 已把 `detail/export.h` 列为随公开头导出, 无需改动。
